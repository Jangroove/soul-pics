## 1. 文書の位置づけ

本書は、設計上の理想仕様ではなく、現行ソースコードに実装されている挙動を記録する実装現況仕様書である。機能追加・不具合修正・提出版との差分確認では、本書と `CURRENT.md`、`CHANGELOG.md` を併用する。

## 2. 製品概要

Soul Pics は、背景・被写体・テキストを独立レイヤーとして編集するブラウザベースの画像コンポーザーである。画像の配置、色調整、テキスト編集、プレビュー、PNG出力はブラウザ内で完結する。被写体切り抜きと背景生成ではローカルCodex App Serverを選択できる。

基本原則:

- 元画像を直接破壊せず、配置・効果・マスクをプロジェクト状態として保持する。
- プレビューとPNG出力は同じCanvasレンダラーを使用し、表示結果と出力結果の差を抑える。
- AI処理は自動実行せず、ユーザーがボタンを押した操作だけで実行する。
- Codex App ServerはローカルNodeサーバーから起動し、結果画像もローカル一時フォルダで受け渡す。

## 5. プロジェクト状態モデル

Reactの `project` 状態は、Canvasサイズ、背景、被写体、テキスト配列、品質調整を保持する。画像はブラウザで読み込んだImageオブジェクトとして扱い、元素材と編集済み素材を分離する。

### 5.1 Canvasプリセット

| 識別子 | 幅 | 高さ | 用途 |
|---|---:|---:|---|
| `youtubeLandscape` | 1280 | 720 | YouTube横長 |
| `youtubeVertical` | 1080 | 1920 | 縦動画・ショート |
| `instagram` | 1080 | 1440 | 縦長SNS投稿 |
| `xHeader` | 1500 | 500 | Xヘッダー |
| `socialIcon` | 400 | 400 | アイコン |
| `custom` | 64–4096 | 64–4096 | 任意サイズ |

カスタムサイズは幅・高さとも64px以上4096px以下に丸める。背景画像が存在しない領域は指定した余白・透明部分の色で塗る。

### 5.2 背景レイヤー

背景はアップロード画像またはAI生成画像を保持する。表示方式は次の4種類。

- Cover: 縦横比を保ったままCanvas全体を埋める。
- Contain: 画像全体を表示し、余白を残す。
- Stretch: Canvas全体へ引き伸ばす。
- Actual size: 1:1ピクセルで配置する。

背景のX/Y位置は数値指定およびプレビュー上のドラッグで変更でき、中央配置へ戻す操作もある。AI生成背景は生成後、アップロード背景と同じローカル編集対象になる。

### 5.3 被写体レイヤー

被写体は元画像、切り抜き画像、表示位置を分けて管理する。編集項目は以下。

- サイズ倍率: 0.1–1.8
- 回転: -180–180度
- X/Y位置
- 左右反転
- 上下反転

反転は現在表示されている回転状態を基準に適用する。切り抜き前の元画像は保持され、切り抜き結果だけを差し替え可能である。

### 5.4 テキストレイヤー

複数レイヤーを配列で保持し、追加・選択・削除・並べ替えが可能である。各レイヤーは次の値を持つ。

- 文字列、X/Y位置、フォント、サイズ
- 太字、Italic、Underline
- 文字色
- 縁取り幅、縁取り色
- 影の色、X/Yオフセット、spread、blur、opacity
- 背景色、背景透明度、左右上下padding、角丸、背景blur

テキストはCanvas中央揃えを基本とし、背景矩形は実際のテキスト計測値とpaddingから算出する。影はシルエットを先に描画し、その後に縁取りと塗りを描画する。

## 6. 画面・操作仕様

### 6.1 ヘッダー

- Soul Pics公式ロゴを表示。
- EN / 日本語を切り替える。
- ダウンロードボタンからPNGを出力する。
- 選択言語は `localStorage` の `soul-pics-language` に保存する。

### 6.2 Canvas設定（Backgroundタブ内）

Canvasプリセット、カスタムサイズ、背景余白色などを変更する。現在の出力幅・高さをプレビュー上部に表示する。

### 6.3 Backgroundタブ

背景生成と背景アップロードを排他的なソース切替UIで提供する。生成時はプロンプトだけを入力し、現在のCanvas幅・高さをCodex App Serverへ渡す。処理中は指定寸法を表示し、返却画像をCanvas寸法へ合わせて背景レイヤーに読み込む。生成はCodexプラン利用枠を使い、Soul PicsのOpenAI APIキーは使用しない旨を表示する。

### 6.4 Subjectタブ

画像をアップロードし、「何を残すか」を日本語または英語で入力してローカル切り抜きを実行する。処理中はオーバーレイを表示する。切り抜き結果または元素材を合成前の状態で保存できる。

### 6.5 Textタブ

テキストレイヤーを追加・選択・削除し、文字・フォント・色・縁取り・影・背景を編集する。既定フォントが用意され、ブラウザのローカルフォント一覧を取得した場合は `soul-pics-local-fonts` に保存する。

### 6.6 Qualityタブ（日本語: 画質調整）

最終画質調整は Weak / Standard / Strong のおすすめ強度と手動スライダーで操作する。リセットは素材、位置、テキストを保持したまま品質調整だけを初期化する。

### 6.7 UI文字サイズ・配色（v1.0.1）

操作UIの文字サイズはCanvas内の作品文字サイズとは別に定義する。`--font-ui: 13px` を操作ラベル、数値、入力、タブ、通常ボタンで共有し、`--font-caption: 12px` を説明・注意・寸法・版表示に、`--font-heading: 14px` をパネル見出しに使用する。ブランド補足は11px、±記号は16px。画面幅によって操作文字を縮小しない。ブランドタイトル自体は既存の独立スタイルを維持する。

| 用途 | 色・表示仕様 |
|---|---|
| ブランド | ライムグリーン `#21ff21` を維持 |
| 操作アクセント | `#a9da73`、強調 `#91c860`、淡色 `#dcf6bd` |
| 主文字 / 操作説明 | `#edf5ef` / `#d4e4d8` |
| 補助文字 / 仮文 | `#b6cbbd` / `#a8bdaf` |
| 入力枠 | `#567866` |
| 選択タブ | 淡いライムのグラデーション＋濃緑文字 `#0b1b0c` |
| 無効ボタン | opacityを下げず、文字 `#aac3b0`、背景 `#183127`、枠 `#4b7058`、影なし |
| Codex利用案内 | 通常の説明文と同じトーンで、Codexプラン利用とSoul Pics APIキー不要を表示 |

深緑のアプリ背景と作品Canvasの既存描画は維持する。UI配色の変更はPNGに描かれる作品色を変えない。通常の選択タブは水色からライム系へ統一し、Codexプラン利用案内は通常の説明色で表示する。

### 6.8 コントロール・改行

- Rangeは「項目ラベル → 数値ステッパー → スライダー」の縦構成。項目ラベルと数値欄を同じ横列に押し込まない。
- 数値ステッパーは `28px / minmax(52px, 1fr) / 28px`、間隔4px、高さ30px。2列の設定グループは `minmax(0, 1fr)` で幅を共有する。
- 狭い場所の文言は文脈を残して短縮する。英語のボタンは `Generate AI` / `Local cutout` / `Save image` / `Upload image`、背景矩形の調整は `Padding X` / `Padding Y` / `Radius`。対象の操作ボタンには詳細文言をtitle/aria-labelとして残す。
- 未使用の旧日本語ラベルを対象にした強制改行処理を撤去。見出しとプレビュー説明は別段に配置し、長い説明文は利用可能幅に応じて自然に折り返す。
- テキストレイヤーボタンは最小88pxかつ自然幅にし、レイヤー番号の不要な折り返しを防ぐ。

### 6.9 レスポンシブ配置

| ビューポート幅 | 配置・スクロール |
|---|---|
| 1241px以上 | 左操作 / 中央プレビュー / 右操作の3列。操作パネル内を縦スクロール |
| 761–1240px | 上段に全幅プレビュー、下段に左右の操作パネル。ページ全体を縦スクロール |
| 760px以下 | 左操作 → プレビュー → 右操作の1列。ヘッダー・通知も縦配置 |
| 380px以下 | 2列の設定グループ、素材アクション、反転を1列にし、サイズとB/I/Uを別行へ配置 |

ブランド補足の2項目目は1440px以下で非表示にし、主要ロゴ・説明・言語・保存ボタンの幅を確保する。320–1920pxの14幅、日英112状態で測定上の横はみ出しと操作欄の重なりがないことを確認した。全ブラウザ・ズーム倍率を保証するものではない。

## 7. Canvas描画仕様

描画順序は背景、被写体、品質効果、テキストである。`renderProject()` がプレビューとPNG出力の双方から呼ばれる唯一の描画入口である。

### 7.1 背景

`backgroundRect()` が表示方式と位置から描画矩形を算出する。Cover / Contain / Stretch / Actual size のいずれでも、Canvasの出力サイズを基準に描画する。

### 7.2 被写体・品質効果

品質調整が有効な場合、被写体にはbrightness、contrast、saturation、blurを適用する。temperatureとcolor spillは色オーバーレイ、sharpnessはコントラスト補正、edge softnessは境界の柔らかさとして扱う。背景にはblur、全体にはgrain、被写体には距離・不透明度・blurを指定できる影を適用する。

### 7.3 PNG出力

表示中Canvasの `toDataURL('image/png')` を使い、プレビューと同一状態をPNGとしてダウンロードする。別の出力専用レンダラーは存在しない。

### 7.4 ドラッグ・ヒットテスト

Canvas表示サイズと実Canvasサイズの比率を座標変換し、テキストを上から順にヒットテストする。テキストに当たらない場合は被写体を対象とする。空白領域のドラッグは背景位置変更に使う。

## 8. API仕様

### 8.1 `GET /api/health`

ローカルAI workerの利用可否、worker起動状態、OpenAIキー設定の有無、ソースバージョンをJSONで返す。外部API呼出しは行わない。

### 8.2 `POST /api/mask`

`multipart/form-data` で画像1枚と `prompt` を受け取る。画像上限は50MB、promptは3–500文字。サーバーは一時ディレクトリへ保存し、ローカルworkerへ処理を依頼する。成功時はRGBA PNGを返す。

処理方針:

1. 入力画像をSharpで検証。
2. promptと画像をローカルworkerへ渡す。
3. 日本語指示を検出用ラベルへ正規化。
4. Grounding DINOで対象候補を検出。
5. SAM 2.1でマスクを生成。
6. BiRefNet系処理で輪郭・アルファを精製。
7. 元画像のRGBと縦横比を維持したPNGを返す。

同一画像とpromptの結果は最大3件のメモリキャッシュへ保存する。キャッシュヒット時は `X-Soul-Pics-Cache: hit` を返す。OpenAI APIは使用しない。

### 8.3 `POST /api/codex-cutout`

`multipart/form-data` で選択画像と `prompt` を受け取る。画像上限は50MB、promptは3–500文字。ジョブごとの一時フォルダに `source.*` を保存し、Codex App Serverで新規スレッドを作成する。画像は `localImage` 入力、選択指示はテキストとしてCodexへ渡し、スレッドの作業場所はそのジョブフォルダに限定する。Codexは同じ場所へ `result.png` を保存する。

ブラウザは `GET /api/work-cutout/:id/status` をポーリングし、Codexターン完了後にSharpでPNG形式・アルファチャンネル・透明画素を検証する。`GET /api/work-cutout/:id/result` で取得したPNGを被写体レイヤーへ読み込む。Codex App Serverの実行にはサインイン済みCodex環境を使い、Soul PicsのOpenAI APIキーは使わない。承認待ちを発生させないよう `workspace-write` と `approvalPolicy: never` を指定する。

### 8.4 `POST /api/background`

JSONで `prompt`、`width`、`height` を受け取る。promptは3–1500文字、寸法は64–4096 px、総画素数は16,777,216以下、縦横比は3:1以内に検証する。

Codex App Serverにimagegen skillとテキスト指示を渡す。画像入力は行わない。Codexはジョブ専用フォルダに `result.png` を生成し、ブラウザは `GET /api/background/:id/status` をポーリングする。完了後にPNGを検証し、Sharpで現在のCanvas幅・高さへcover crop/resizeしてから返す。ジョブフォルダは24時間後の定期掃除対象となる。

## 9. ローカルAIの実行境界

ローカルAI workerは起動時にオフライン設定を受け、モデルキャッシュから読み込む。環境変数 `SOUL_PICS_PYTHON`、`.local-ai/.venv/Scripts/python.exe` 等からPython実行ファイルを検出する。モデルキャッシュは `SOUL_PICS_MODEL_CACHE` 等から検出する。

worker停止時は保留中リクエストを失敗扱いにし、切り抜きのタイムアウトは10分である。処理後の一時ディレクトリは削除する。

## 10. セキュリティ・プライバシー・料金

- Codex App Serverはサインイン済みCodex CLIのプラン利用枠を使用する。
- ローカル切り抜きでは被写体画像とpromptを外部へ送信しない。
- Codex切り抜きボタンを押すと、選択画像とpromptをCodex App Server経由でCodexへ送る。Codexプラン利用枠を使い、Soul PicsのOpenAI APIキーは使わない。
- Codex切り抜き・背景生成は明示ボタン操作時だけ実行する。
- 起動時、プレビュー時、品質調整時にAPIを自動呼出ししない。
- 自動リトライを行わない。
- 通常編集・品質調整・PNG出力はAPI料金不要。
- 背景生成はCodexプラン利用枠を使用し、Soul PicsのOpenAI APIキーは使わない。
- アップロード画像はメモリおよび一時領域で処理し、処理後の一時領域を削除する。
- 配布物へ `.env`、APIキー、`.local-ai`、モデルキャッシュ、`node_modules` を含めない。

## 11. エラー・状態表示

API状態は起動時に `/api/health` で確認する。ローカルAI未導入、Codex CLI未導入、Codexタスク失敗、画像形式不正、対象未検出、GPUメモリ不足を個別メッセージへ変換する。AI処理中は処理内容と目安をオーバーレイ表示し、成功・失敗・キャンセル時に解除する。

## 12. 既知の制約・未実装

- 手動マスクブラシは未実装。
- Undo / Redo は未実装。
