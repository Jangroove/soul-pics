# Soul Pics 画面デザイン点検結果

点検日: 2026-09-30（日本時間）\
対象: `Source/Soul_Pics`、v1.0.0、HEAD `c991d11` と現在の作業ツリー\
範囲: UIの文字サイズ、重なり・はみ出し、改行、画面幅への対応\
状態: 修正前の点検記録。共通化・修正案はその後v1.0.1に実装済み（[実装報告](09_UI_REFINEMENT_2026-09-30.md)参照）。以下は点検時点の状態。

## 1. 結果

文字サイズの共通化と、テキスト編集コントロールの再配置が必要。日本語の通常デスクトップ表示では大きな横方向の崩れを検出しなかったが、英語のラベルは広い画面でも数値欄と重なる。1180px以下の3列レイアウトでは、日本語・英語ともに文字サイズの数値ステッパーが隣のB/I/Uコントロールに侵入する。

ページ全体の横方向スクロールは今回の64状態では発生しなかった。これは個々のコントロールに重なりがないことを意味しない。パネル内の縦スクロールは有効で、下部の項目にはスクロールして到達できる。

## 2. 点検方法・証拠

現行 `src/`、`public/`、package情報、Vite設定を一時環境へコピーし、固定された依存関係を導入してChromeのヘッドレス実表示を確認した。正本の `node_modules` にはVite実行ファイルがなく、通常の `npm run dev` は起動できなかったため、この方法を使用した。

- 言語: 日本語・英語
- 画面サイズ: 1920×1080、1366×768、1180×820、1024×768、961×720、960×720、620×800、375×812
- 各言語・各サイズで、初期画面、被写体、画質調整、背景アップロードの4状態を確認（計64状態）
- 実効フォントサイズ、要素境界、内容幅、パネルのスクロール領域を測定
- 1366px、1024px、375pxの代表画面を画像で確認
- `/api/health` は準備未完了の固定応答を使用。AI実行、モデル起動、有料API呼出しは行っていない

測定データと画像: [`../../work/ui-audit-2026-09-30/`](../../work/ui-audit-2026-09-30/)\
再実行用スクリプト: [`audit.cjs`](../../work/ui-audit-2026-09-30/audit.cjs)\

## 3. 問題一覧と修正案

### UI-01: 英語ラベルが数値操作に重なる（優先度: 高）

テキスト背景の `Horizontal padding`、`Vertical padding`、`Corner radius` が、同じ行の数値ステッパーへ侵入する。

| 画面幅 | ラベル | 利用可能幅 | 文字内容幅 |
|---|---|---:|---:|
| 1920px / 1366px | Horizontal padding | 44px | 88px |
| 1920px / 1366px | Vertical padding | 44px | 74px |
| 1920px / 1366px | Corner radius | 44px | 61px |
| 1024px | Horizontal padding | 26px | 82px |
| 1024px | Vertical padding | 26px | 69px |
| 375px | Horizontal padding | 約60px | 82px |

日本語も1180px以下の3列表示では「左右余白」「上下余白」が、利用可能26pxに対して約36px必要となる。

原因: `.range-header` はラベルと数値欄を横並びにする一方、`.editor-block .range-title` は `white-space: nowrap`。小さい2列セルに固定幅ステッパーを配置するため、ラベル幅が不足する。

関連: `src/styles.css:758`、`src/styles.css:1003`、`src/styles.css:1009`、`src/styles.css:1058`。

修正案: 2列の小型コントロールでは「ラベル行」「数値操作行」「スライダー行」を分ける。文字の途中を改行する前に、ラベルが1行で収まる領域を確保する。必要なら英語の表示ラベルを `Padding X` / `Padding Y` / `Radius` に統一し、詳細説明はtitle等で補足する。

証拠: [英語1024px](../../work/ui-audit-2026-09-30/en-1024x768-initial.png)、[英語375px](../../work/ui-audit-2026-09-30/en-375x812-initial.png)。

### UI-02: 文字サイズステッパーがB/I/Uに侵入（優先度: 高）

1180px、1024px、961pxの3列表示で、日本語・英語ともに再現。1024pxでは文字サイズヘッダーの幅128pxに対し、内容は146px必要。ステッパーが18px右にはみ出して「＋」とB操作が重なる。

原因: `.text-size-style-row` がB/I/U用102pxを固定確保し、その残りにラベルと幅110pxの数値欄を並べる。ラベル最小30pxとgap6pxを加えると146px必要となり、残り128pxには収まらない。

関連: `src/styles.css:760`、`src/styles.css:1017`、`src/styles.css:1019`。

修正案: サイズのラベルと数値操作を2段に配置する、または狭いパネルではB/I/Uを別行へ移す。文字サイズやボタンをさらに縮小して解決する方法は採らない。

### UI-03: 同じ役割の文字サイズがばらつき、数値が小さい（優先度: 中）

| 要素 | 1180px超 | 1180px以下 |
|---|---:|---:|
| 一般ラベル / フォント見出し | 11.7px | 10.92px |
| 一般入力・選択欄 | 12px | 11.2px |
| 一般アクションボタン | 12.3px | 11.48px |
| 背景・被写体アクションボタン | 10.2px | 9.52px |
| テキスト位置・余白ラベル | 9.6px | 8.96px |
| 被写体の数値 | 9px | 8.4px |
| テキスト位置・余白等の数値 | 8.4px | 7.84px |
| PCフォント取得ボタン | 8.25px | 7.7px |

幅1180px以下でルート文字サイズが15pxから14pxになるため、狭い画面ほど文字が小さくなる。小さな数値欄やPCフォント取得ボタンは識別しにくい。

関連: `src/styles.css:7`、`src/styles.css:465`、`src/styles.css:871`、`src/styles.css:880`、`src/styles.css:890`、`src/styles.css:906`、`src/styles.css:933`、`src/styles.css:1060`。

共通化案（提案値。未適用）:

| 役割 | 共通サイズ案 | 方針 |
|---|---:|---|
| パネル・グループ見出し | 14px | 色・太さ・余白で階層を区別 |
| ラベル、入力値、数値欄、タブ、ボタン | 13px | 同じ操作系で共通化 |
| 補足説明、状態、補助ボタン | 12px | PCフォント取得もこのサイズに含める |
| 装飾用メタ情報 | 11px | 操作に必要な内容には使わない |

CSS変数で役割別サイズ・行高を定義し、個別の `.56rem` 等を整理する。画面幅が狭い場合は、文字を縮小する前に列数・操作の並び・パネル幅を変更する。文字拡大にはレイアウト修正も必要。

### UI-04: 改行を防ぐ設定と横並びが衝突（優先度: 中）

英語1024pxでは背景ソースタブと生成・保存ボタンが2行になる。英語1920pxでは問題が少ないが、2列操作幅が不足する画面では文言が長いため自然改行が起きる。これは強制改行ではない。

プレビュー上部では固定幅の `SOUL CANVAS / LIVE PREVIEW` と説明文が横並びになっている。1024pxでは説明欄が約4行、961pxでは約5行に増え、見出し高さが約61px / 約76pxとなる。

関連: `src/styles.css:600`、`src/styles.css:608`、`src/styles.css:849`、`src/styles.css:870`、`src/main.jsx:384`。

修正案: 操作ボタンは短い表示文言と十分な幅を用意して1行を優先する。プレビュー見出しは狭い場合にタイトルと説明を上下に配置し、説明文を極端に狭い横幅へ押し込まない。補足説明文の自然改行は許容する。

### UI-05: 古い強制改行ルールが残存（優先度: 低）

`Controls.jsx` の `Range` に「影の広がり」「影の濃度」を `<br />` で分割する処理がある。ただし現行画面は「広がり」「透明度」「影の濃さ」等を渡しており、今回の64状態でこの強制改行は0件だった。

関連: `src/components/Controls.jsx:69`、`src/components/Controls.jsx:77`。

修正案: 将来のラベル変更で突然2行になることを防ぐため、名称に依存した強制改行を共通コントロールから取り除く。ラベルの折返しは利用可能幅に応じたCSSにまとめる。

## 4. 縦方向の表示

1366×768のテキストパネルは、表示領域約493pxに対して内容約891px。画質調整パネルは約1071pxである。1920×1080でもテキストパネルは表示領域約805pxに対して内容約891pxなので、最下部まで同時には表示されない。

縦スクロールで到達できるため、項目消失の不具合とは判定しない。ただし、文字を拡大する際に「すべてを1画面へ押し込む」前提を維持すると再び窮屈になる。グループの余白を整理し、スクロール可能であることを分かりやすく示す。

## 5. 修正後に確認する条件

1. 日本語・英語双方でラベルが数値欄と重ならない。
2. サイズの「＋」とB/I/Uに重なりがなく、それぞれ操作できる。
3. 数値・入力・ラベルが共通サイズで表示される。
4. 狭い画面で文字がさらに小さくならない。
5. 操作ラベルに不要な固定改行がない。
6. 長い説明文は自然に折り返し、パネル外へ出ない。
7. パネル下部へスクロールして到達できる。
8. 既存の配置操作とPNG出力が維持される。

## 6. 点検の限界

Chrome、DPR 1、通常のブラウザ拡大率で確認。実GPU切り抜き中、OpenAI生成中、OS側の拡大率、他ブラウザ、特殊フォント・極端に長い通知、画像読込後に追加される背景位置操作は今回の表示測定の対象外。現在の報告は調査結果と修正方針であり、修正済み・回帰確認済みとは扱わない。
